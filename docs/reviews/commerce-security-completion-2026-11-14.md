## Concrete findings and focused acceptance

**F1 — Browser account-switch privacy candidate; potential high impact conditional on state persistence, not a reproduced remote exploit.** `App.tsx:166–175` clears React Query without remounting identity-sensitive components. Public `screens/checker.tsx:30–34,47–50` keeps copied profile facts/results in state and remains mounted at sign-out. `screens/profile.tsx:28–38` initializes only once; line 54 submits local fields with the current workspace revision. If account switching preserves that subtree, old information can remain visible or contaminate the next profile. Attacker condition: access to the same browser/session transition, not a guessed tenant ID. **Fix/test:** key/reset state by identity/session, cancel stale work and check callback epoch. Two accounts with distinct markers; active switch, other-tab sign-out, delayed responses and Back/Forward. No prior marker in DOM/forms or subsequent payloads. API 401 alone is insufficient.

**F2 — Inconsistent development-only gates.** `valo-exports.ts:14–16` rejects only `NODE_ENV=production`; startup has no stronger guard. Unset/test or development plus deployment marker can reach exports. `valo-reminder-resend.ts` rejects only `REPLIT_DEPLOYMENT==='1'`. This is a configuration-dependent release-gate defect, not tenant bypass. **Fix/test:** require explicit development and no nonempty deployment marker before queue/storage/transport effects. Reject unset/test/production and markers `1`, `true`, arbitrary nonempty strings; fake transports suffice.

**F3 — Refund/dispute lifecycle stops at intake.** `requestRefund()` only stores `requested`; unique order ID prevents later partial requests. No amount/provider reference/attempt ledger or finance mutation exists. Webhook handling supports only `charge.success`. **Fix/test:** finance role/fresh MFA, audited approve/reject, immutable kobo amounts and references, cumulative reserved/completed refund bound under order lock, timeout recovery and authoritative statuses. Race partial requests; duplicate/reference conflicts, timeout after acceptance, reordered events, other-tenant/wrong-role requests. Preserve customer drafts and use a versioned explicit test entitlement policy. No money-theft exploit is established while execution is disabled.

**F4 — Receipt history/reconciliation omissions.** `purchaseReceipt()` rejects reversed orders; `display()` removes their receipt reference. Reconciliation checks only entitlement, so a missing receipt outbox can still be `matched`; same-success settlement returns before repairing it. **Fix/test:** immutable original receipt plus clear reversal/refund state; detect both grant and receipt gaps and perform audited idempotent compensation. Test reversal retrieval, missing grant/outbox and concurrent repair without duplicate effects.

**F5 — Worker starvation.** `workers/export-worker.ts` awaits reminders before payment inbox/reconciliation inside one try. A recurring invalid/revoked-owner reminder can prevent payment work every dispatch. Reminder selection has a limit of 25, no fairness, and persistent held rows with no retry delay can crowd out later work. **Fix/test:** independent guarded lanes/clocks; park and explicitly reawaken holds or use durable fair selection. Queue 25 persistent holds, an eligible 26th and a payment event; fake-sender dispatch/payment processing must both eventually occur once.

**F6 — Privacy/deletion/retention lifecycle missing.** `requestPrivacy()` is an unstructured support ticket. Structured tenant export has row/byte refusal but explicitly excludes private file bytes, managed identity/providers and unlinked public contacts. No coordinated correction/erase/legal-hold state machine or account-deletion tombstone exists. `valoFileAssets.retentionAt` is nullable and unset by successful export creation; orphan cleanup preserves referenced assets. **Fix/test:** typed verified requests, audited staff transitions, policy-bound resumable orchestration, legal-hold exclusions, pending-job cancellation and object cleanup. Interrupt/retry synthetic erasure, account for each system, and replay deletion tombstones after restore. Never claim partial completion or invent a universal retention period.

**F7 — Per-merge security checks/logging proof missing.** `.github/workflows/valo-foundation.yml` runs PR-to-main/feature-push tests but lacks main-push, dependency audit and secret-scanner jobs. **Fix/test:** credential-free scans on merges, frozen-lock dependency checks, redacted reports and safe detector canaries that fail. Never plant a real credential. Capture actual HTTP/error logs with synthetic private markers; the current “without logging private input” test checks `providerRuns`, not logger output. Historical regex scans are not fresh full-history assurance.

**F8 — Recovery/readiness implementation and proof remain incomplete.** Add bounded DB/worker/backlog/cleanup/payment-mismatch readiness and alert records, tested without external sends. Isolated restore harness should suppress charge/refund/email, replay revocations/deletions, check tenant/object consistency and measure actual elapsed/cutoff times. Production target/settings and owner decisions are external inputs; the harness/synthetic tests are not blocked by them. Static liveness must not be called dependency monitoring.
