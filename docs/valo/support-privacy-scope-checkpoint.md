# Support details and honest workspace export scope

This is a partial development checkpoint, not privacy fulfilment, authorised
staff/MFA acceptance or R1/R2 completion.

## Working changes

- Support uses complete request cards rather than the first eight keys of a
  mixed table. Public messages and private scopes both remain available in native
  keyboard-operated disclosures, with category/topic, contact, consent and dates.
- Long text wraps at mobile widths; user-supplied markup is rendered as text.
- The account privacy screen and actual JSON export explain that only the named
  sections are included. File bytes/job metadata, membership/audit records,
  identity-provider records, external-provider data and unlinked public contacts
  are not part of this copy. It is not complete privacy fulfilment.
- The staff introduction no longer incorrectly calls finance actions read-only.

## Executed evidence

The retained JSON report contains exact source hashes, all three final browser
groups, type-check command/output/exit status and a fresh public-count observation.

1. Actual managed synthetic signup, verification and private-route access.
2. The real staff endpoint denied that customer. Only the staff-display response
   was intercepted with synthetic mixed records: complete text, escaped markup,
   native Enter/Space disclosure, visible focus, 360px and desktop reflow passed.
   This is explicitly **not** a real privileged staff/MFA session.
3. A real privacy request survived reload and remained `awaiting_staff`. A real
   saved document revision appeared in the private no-store JSON download; its
   exclusions were present in both the screen and actual response.

The final browser run removed its synthetic identity and owned application rows
with zero cleanup errors. One intermediate harness-observation failure is retained
separately, rather than discarded or presented as a product failure.
