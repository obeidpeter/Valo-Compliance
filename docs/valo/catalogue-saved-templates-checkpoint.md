# Catalogue discovery and saved templates

This private-development unit adds keyword relevance, category/industry/type/access
filters, relevance/name/recently-checked sorting, URL persistence, pagination,
reset and useful empty states. Search takes current eligible public metadata.
Industry directory and service enquiry pages are clearly distinguished from
released guidance and available professional providers. No customer draft,
unpublished candidate or paid source file enters the search index.

Active workspace owners can save and remove a released template. The database
deduplicates by workspace and canonical template identity. A public title/version
snapshot remains useful when a template is withdrawn; its current link then
disappears. Suggestions use supplied activity and saved categories, carry an
explanation and never assert a legal duty or grant an entitlement. Saved metadata
is included in the scoped workspace export and existing bounded erasure phase.

Public detail metadata and the sitemap use current release metadata and a
configured origin, never request Host headers. Account, admin, draft, unknown and
withdrawn paths do not enter the sitemap. This remains a development build with
no-index headers and robots exclusion; no public launch was enabled.

Validation includes 50 controlled search queries plus filtering, pagination,
recommendation and metadata boundary checks; actual PostgreSQL ownership,
concurrency, revocation and unavailable-item tests; saved-item erasure regression;
and a controlled browser journey using the real components and generated client.
The positive storage fixture controls only release selection and never publishes
its held database candidate. Browser fixture data does not prove genuine Clerk
identity, publication acceptance or production visual acceptance.
