## Required integration

- Independently validate the expected outcomes against the retained authoritative contract and actual final source passages. Root review corrected an ambiguous quotation-commitment case, a contradictory geography field and non-contract applicability labels; that review is not a substitute for required provider-backed evaluations.
- Build actual runners in Replit and bind each execution to its precise application, policy, rule, source, prompt/model and candidate versions. Never convert the candidate metadata into a pass result.
- Checker expectations are conditional on real reviewed released versions. An unreleased, expired or out-of-scope rule must remain unavailable in the live engine. The four source candidates do not by themselves establish complete RUL-008 coverage, 30 eligible guidance entries or state/LGA coverage. Expand the corpus when additional released rules and threshold-sensitive claims become available.
- Customer AI cases need actual provider runs except explicitly identified isolated fault-injection controls. Keep real model-quality results distinct from synthetic outage/schema/permission mechanics. Record the applicable numeric range and exact decimal calculations; unsupported values may be rejected clearly but may not silently round.
- Editorial positive cases require actual rights, source, separate reviews and mechanical/export evidence. Failure cases must exercise actual controls, including independent publisher permissions and atomic state changes. A conditional expected publication is not an approved publication.
- Retain failures and reruns. Apply the original three separate acceptance standards; all critical outcomes must pass and AI suites require the specified quality threshold. No legal-accuracy certification is established by these suites.

The existing user-approved master specification remains authoritative. These datasets accelerate implementation and review; they cannot waive a source, commercial, privacy, security, recovery or release gate.
